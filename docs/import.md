# Importing from PostgreSQL

`basinctl import-from-postgres` is the onboarding tool: point it at a
running PostgreSQL and a running Basin, and it migrates schemas, tables,
and data in one pass.

```sh
basinctl import-from-postgres \
  --source postgres://app:secret@db.internal:5432/app \
  --target postgres://alice@127.0.0.1:5433/basin \
  --jobs 8
```

What it does, in order:

1. **Enumerate** every non-system schema on the source via
   `information_schema` (joined with `pg_catalog.format_type` to recover
   what information_schema loses: `vector` dimensions, `geometry`
   subtypes, enum-ness).
2. **Translate** the DDL into Basin's dialect (table below), recording a
   loud per-object skip report for everything Basin handles differently.
3. **Create** enum types and tables on Basin, in foreign-key dependency
   order. A failing `CREATE TABLE` retries down a ladder — full → without
   CHECK constraints → without CHECKs and FKs — and reports whatever it
   had to drop.
4. **Stream data** per table: `COPY (SELECT …) TO STDOUT (FORMAT BINARY)`
   on the source piped straight into `COPY t (…) FROM STDIN (FORMAT
   BINARY)` on Basin. Tables whose column set Basin's binary COPY can't
   decode automatically use CSV instead. `--jobs N` tables stream in
   parallel — but only within one FK level, so parents always land before
   children and Basin's FK enforcement on ingest never trips.
5. **Verify** per-table row counts (source snapshot vs Basin `count(*)` vs
   the COPY-reported row count — the source is read inside a single
   `REPEATABLE READ, READ ONLY` transaction per table so the count and
   the stream see the same snapshot), bump identity sequences past
   `MAX(col)` via `setval`, and print a final summary. Exit code is
   non-zero if any table failed or any count mismatched.

## Flags

| Flag | Default | Meaning |
|------|---------|---------|
| `--source <url>` | required | Source PostgreSQL connection string |
| `--target <url>` | `--url` / `BASIN_URL` | Target Basin pgwire endpoint |
| `--schema <name>` | all non-system | Import only these schemas (repeatable) |
| `--table <name>` | all | Import only these tables, bare or `schema.table` (repeatable) |
| `--jobs <n>` | 4 | Tables copied in parallel within an FK level |
| `--dry-run` | off | Print the translated DDL + skip report; touch nothing |
| `--skip-data` | off | Create tables only, copy no rows |
| `--format auto\|binary\|csv` | auto | Transfer format; `auto` decides per table |

Connections use the same conventions as the rest of `basinctl`: plain
TCP, no TLS (`sslmode=require` sources are not supported yet).

## Type mapping

| Source (PG) | Basin | Transfer | Notes |
|-------------|-------|----------|-------|
| `smallint` / `integer` / `bigint` | same | binary | |
| `smallserial` / `serial` / `bigserial` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | binary | Basin's identity convention; stream cast to `int8`; sequence `setval`'d past `MAX(col)` after load |
| `GENERATED { ALWAYS \| BY DEFAULT } AS IDENTITY` | same, declared width | binary | sequence options (START/INCREMENT) not carried |
| `boolean`, `real`, `double precision` | same | binary | |
| `text` / `varchar(n)` / `char(n)` | same | binary | |
| `numeric(p,s)` | `NUMERIC(p,s)` | binary | `p > 38` clamps to 38 (warn); bare `numeric` → `NUMERIC(38,18)` (warn) |
| `bytea`, `date`, `timestamp`, `timestamptz` | same | binary | |
| `uuid` | `UUID` | binary | extension type, native in Basin |
| `jsonb` | `JSONB` | binary | |
| `json` | `JSONB` | binary (`::jsonb` cast) | Basin canonicalises key order/whitespace (warn) |
| `citext` | `CITEXT` | binary | extension type, native in Basin |
| enum types | `CREATE TYPE … AS ENUM` recreated first | binary | label text on the wire |
| `time` | `TIME` | csv | no binary codec on the Basin side |
| `interval` | `INTERVAL` | csv | PG text form on the wire (warn: verify a sample) |
| `money` | `MONEY` | csv (`::numeric` cast) | avoids locale-formatted text |
| `inet` / `cidr` / `macaddr` / `macaddr8` | same | csv | |
| `bit(n)` / `varbit` | same | csv | |
| `xml` | `XML` | binary | |
| `tsvector` / `tsquery` | same | csv | canonical text form |
| `int4range` … `tstzrange` | same | csv | reshaped to Basin's JSON range encoding on the source; empty ranges not representable |
| arrays (`int[]`, `text[]`, …) | `ELEM[]` | csv | PG array-literal text (warn: verify a sample) |
| `vector(n)` (pgvector) | `VECTOR(n)` | csv | bare `vector` (no dim) is skipped |
| `point` | `POINT` | csv | reshaped to WKT `POINT(x y)` |
| `geometry(Point[,srid])` (PostGIS) | `GEOMETRY(POINT[, srid])` | csv (`ST_AsText`) | non-Point subtypes skipped |
| domains | underlying type | as underlying | flattened (warn) |
| `timetz`, composites, `txid_snapshot`, … | — | — | column skipped with a report; if NOT NULL without default, the whole table is skipped |

Column `DEFAULT`s carry over only when portable: literals, `now()` /
`CURRENT_TIMESTAMP` / `CURRENT_DATE`, `gen_random_uuid()` /
`uuid_generate_v4()`. Anything else is dropped with a warning.

## The skip report

Basin is not Postgres, and the importer never pretends otherwise. Every
object it cannot carry lands in the report — once at the moment it is
discovered (stderr) and again in the final summary:

```
SKIP trigger    public.users.audit_trg — triggers are not imported (rewrite as a Basin reactor (CREATE REACTOR … ON INSERT/UPDATE/DELETE))
SKIP function   public.fn_touch() — plpgsql functions are not imported (port to a Basin WASM function — see `basinctl fn` for the toolchain roadmap)
SKIP view       public.order_totals — view bodies are not imported (re-create with CREATE VIEW on Basin after checking the SQL against docs/sql-support.md)
SKIP constraint public.bookings.no_overlap — EXCLUDE constraints are not supported (enforce in application code or a reactor)
```

Skipped categories and their Basin-shaped migration paths:

- **Triggers** → Basin **reactors** (row-change logic in the engine).
- **plpgsql / SQL functions** → Basin **WASM functions**
  (`docs/functions.md`; `basinctl fn` prints the toolchain roadmap).
- **Views / materialized views** → re-create on Basin (views) or use a
  continuous pre-aggregation (matviews).
- **EXCLUDE constraints** → application code or a reactor.
- **Self-referential FKs and FK cycles** → dropped so bulk load can
  proceed (Basin enforces FKs on ingest and has no
  `ALTER TABLE … ADD FOREIGN KEY` to defer them).
- **FKs pointing outside the import set** → dropped; import the
  referenced table in the same run to keep them.

## Naming across schemas

Basin's namespace is flat per project (user schemas alias to `public`).
Tables import under their bare name; when the same bare name exists in
two source schemas, non-`public` copies are prefixed
(`app.users` → `app_users`) with a warning.

## Verification and failure semantics

- Per table: source snapshot `count(*)`, the COPY-reported row count, and
  Basin `count(*)` must all agree, or the table is flagged
  `COUNT MISMATCH`.
- A binary COPY *refused at start* (e.g. Basin's `0A000` "no binary
  codec") retries once as CSV. A *mid-stream* failure does not retry —
  rows may already have landed; the table is reported failed.
- **Retry-safety (exactly-once).** Re-running a `COPY`/`INSERT` after a
  mid-stream drop is duplicate-free only for tables with a `PRIMARY KEY` /
  `UNIQUE` key: the bulk path enforces the key against all committed files, so
  a re-sent committed row is rejected (or silently dropped under
  `ON CONFLICT (cols) DO NOTHING`, the recommended retry shape). Keyless append
  tables have no key to dedup against, so a blind re-send duplicates rows —
  declare a key (or `ON CONFLICT DO NOTHING`) to make a keyless load
  retry-safe. See `docs/architecture.md` §4 "Durability vs. exactly-once".
- Exit code is non-zero when any table failed or mismatched, so the
  command is safe to script.

Re-running after a partial import: Basin will reject `CREATE TABLE` for
tables that already exist (reported as skipped). Drop them on Basin
first, or use `--table` to import just the stragglers.
