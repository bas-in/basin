Basin v57 vs Neon free tier, co-located fra loader, identical workload, cold and warm both measured (warm = steady-state p50, cold = first-touch). Honest-comparative: the analytical-scan wins are real, and so are the losses.

Per-size verdict (warm, win/loss/tie): 10k = 11/21/2 (Basin loses small-scale point ops), 100k = 17/15/4 (Basin pulls ahead), 1M = 12/11/1 (Basin ahead). Cold first-touch is loss-heavy at every size — Basin reads from object storage (Tigris) on the first touch (~25–50ms/file), Neon reads local SSD; the cache helps repeat reads, not the first miss. The cards below isolate Basin's strongest 1M warm scans plus the honest losses.

Scale (Basin-only — Neon free tier caps at 512MB so it cannot hold these): narrow_pk 1M seed 230k rows/s (point_lookup 4.1ms, range 4.4ms, full_agg 6.8ms warm); 10M seed 145k rows/s (cold reads climb: point 53.6ms, full_agg 225ms). A narrow_nopk 1B run is in progress — see the scaling card.
